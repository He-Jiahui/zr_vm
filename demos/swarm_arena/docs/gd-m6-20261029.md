## Reproduce

The Linux Release build used GCC 14.2.0, system libffi, network and the C session
binding enabled. No Cargo invocation or extra package installation is needed.
Initialize the pinned submodules required by this checkout first. Build only
under the isolated root; select one job below 6 GiB available memory, at most
two otherwise.

```sh
export TMPDIR=/workspace/cargo-targets/zr-gd-m6/tmp
export PYTHONDONTWRITEBYTECODE=1
mkdir -p "$TMPDIR"
cmake -S . -B /workspace/cargo-targets/zr-gd-m6/release -G Ninja \
  -DCMAKE_C_COMPILER=/usr/bin/gcc -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DZR_VM_BUILD_DEMOS=ON \
  -DBUILD_TESTS=ON -DBUILD_CLI=ON -DBUILD_NETWORK_LIB=ON \
  -DBUILD_RUST_BINDING=ON -DBUILD_LANGUAGE_SERVER=OFF \
  -DBUILD_LANGUAGE_SERVER_EXTENSION=OFF -DPython3_EXECUTABLE=/usr/bin/python3 \
  -DZR_VM_LIBFFI_INCLUDE_DIR=/usr/include/x86_64-linux-gnu \
  -DZR_VM_LIBFFI_LIBRARY=/usr/lib/x86_64-linux-gnu/libffi.so
jobs=$(awk '/MemAvailable/ {print ($2 < 6291456 ? 1 : 2)}' /proc/meminfo)
cmake --build /workspace/cargo-targets/zr-gd-m6/release -j"$jobs" \
  --target zr_swarm_aot_host zr_vm_cli_executable zr_swarm zrgame_plugins \
  zrgame_ffi zrgame_native_tests zr_vm_ssa_aot_runner_coverage_test
python3 -I demos/swarm_arena/tools/run_aot.py \
  --cli /workspace/cargo-targets/zr-gd-m6/release/bin/zr_vm_cli \
  --aot-host /workspace/cargo-targets/zr-gd-m6/release/bin/zr_swarm_aot_host \
  --native-dir /workspace/cargo-targets/zr-gd-m6/release/demos/swarm_arena/native \
  --lib-dir /workspace/cargo-targets/zr-gd-m6/release/lib \
  --out /workspace/zr_vm-review/evidence/gd-m6-20261029/aot-rerun
```

`--out` must be a new directory, so stale generated C/libraries cannot pass a
later run. The recorded delivery is `aot-acceptance/`, with 59 commands, separate
logs, staged projects, generated C, shared libraries, identities and findings in
`result.json`. The probe intentionally exits **1 / FINDINGS** on these engine
failures. It is not registered as a passing CTest. Its Markdown/JSON perf rows
contain null measurements; this probe does not implement workload timing.

Each staged lane project retains every original script and dependency but
changes its manifest entry to `lanes/dod/<module>`. This is necessary because
the stock compiler visits the project entry first and stops on its first
lowering failure. No original source is rewritten. The three additional tool
entries exercise the existing game exports, counting-sort grid and bullet-store
reuse/history. Subset checksums are functional controls, not simulation goldens
or W3/W5 performance measurements.

The generated libraries use `-O3 -DNDEBUG -DZR_RELEASE -DZR_PLATFORM_UNIX`,
`-fPIC -shared -fno-fast-math -ffp-contract=off`, the same runtime shared
libraries, an explicit rpath, and `--no-undefined`. They are placed in the
runtime's `bin/aot_c/lib/zrvm_aot_<sanitized-module>.so` locations. Every library
undergoes `RTLD_NOW` load and ABI/backend/module/entry validation. **19 builds
and 19 descriptor loads pass**, including repeated dependencies across staged
projects; that count is not 19 distinct DOD modules.

`zr_swarm_aot_host` reuses `tests/benchmarks/aot_runner` registration, checksum,
result validation and coverage contracts. An entry is registered only after
its compiled descriptor loads. The callback uses
`ZrLibrary_AotRuntime_ConfigureGlobal(...AOT_C, true)` and `ExecuteEntry` in a
protected call, and requires the runtime AOT execution marker. Whole-entry
interpreter fallback is disabled. Semantic-site sampling is not supplied;
coverage remains **UNAVAILABLE**, including for the successful scalar control.
Descriptor inspection alone does not prove successful runtime binding.

## Results and findings

| Original DOD module | Emit | C build / descriptor load | Runtime evidence |
|---|---|---|---|
| `world` | pass | pass, ABI 17, 9 thunks | grid subset rejects its call bindings |
| `bullet_store` | pass | pass, ABI 17, 6 thunks | bullet subset rejects its call bindings |
| `grid` | pass | pass, ABI 17, 4 thunks | subset cannot complete |
| `pickup_store` | pass | pass, ABI 17, 4 thunks | descriptor checked; gameplay blocked |
| `systems` | fail | unavailable | `drain`, function 6, instruction 7, opcode 204 |

**AOT-M6-01 — lowering rejects the supplied main/systems sites.** The normal
project fails at `main.run`, function 2, instruction 115. The independent
systems entry fails at `systems.drain`, function 6, instruction 7. Both report
opcode **204**, `LOGICAL_EQUAL_SIGNED_CONST` in this revision. See
`full-game-emit.log` and `lane-systems-emit.log`. An additional simplified
equality example in `minimal-eq-204/` compiles successfully, so this evidence
does not establish that every signed constant equality is unsupported.

**AOT-M6-02 — config lowering blocks the dedicated smoke entry's graph.**
The wrapper emits some C before `config.parse` fails at function 5,
instruction 76, opcode **226**, `KNOWN_NATIVE_MEMBER_CALL_RECV_U8`.
See `game-smoke-emit.log`. No complete game graph is published.

**AOT-M6-03 — generated call bindings reject runnable subsets.** All C for
the grid and bullet subsets builds and loads, but strict execution reports
`target-kind-mismatch`, expected `0x0`, actual `0x2`:

| Subset | Rejected module | Method token | Instruction | Candidate |
|---|---|---|---:|---:|
| smoke wrapper | `_m6_smoke` | `0x03000002` | 34 | 4 |
| grid | `lanes/dod/world` | `0x03000003` | 121 | 0 |
| bullet store | `lanes/dod/bullet_store` | `0x03000003` | 43 | 2 |

The grid/bullet outer error is `generated AOT dynamic call failed`; the probe
also retains the module-loader diagnostic identifying the failed binding.
See `game-{smoke,grid,bullets}-execute.log`. These are invocation failures,
not observed hash mismatches. The JSON parity field is null when no AOT
checksum exists.

| Entry/control | Interpreter checksum/hash | AOT checksum | Parity |
|---|---:|---:|---|
| standalone scalar | 424242 | 424242 | pass (scalar only) |
| 120-frame smoke wrapper | 552988638 | unavailable | unavailable |
| grid functional subset | 194005223 | unavailable | unavailable |
| bullet functional subset | 787117519 | unavailable | unavailable |

The ordinary CLI smoke and wrapper both retain all committed smoke state
fields, including checkpoint 60 **42922906**. The scalar wrong-checksum control
exits 1 with `CHECKSUM_MISMATCH` and its actual 424242 value; a missing library
exits 1 with `UNAVAILABLE / ENTRY_UNAVAILABLE`, with `entry_invoked=0`. Neither
failure invokes an interpreter replacement.
