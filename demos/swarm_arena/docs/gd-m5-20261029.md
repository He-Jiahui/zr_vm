## Build and run

Use an isolated build root and an owned temporary directory. This run used
GCC 14.2, Release, system libffi and `-j1`, with both network and binding ON.
The binding's shared C ABI supplies the session implementation; Cargo is
not needed to call it from the C host.

```sh
export TMPDIR=/workspace/cargo-targets/zr-gd-m5/tmp
mkdir -p "$TMPDIR"
cmake -S . -B /workspace/cargo-targets/zr-gd-m5/release -G Ninja \
  -DCMAKE_C_COMPILER=/usr/bin/gcc -DCMAKE_BUILD_TYPE=Release \
  -DZR_VM_BUILD_DEMOS=ON -DBUILD_TESTS=ON -DBUILD_CLI=ON \
  -DBUILD_NETWORK_LIB=ON -DBUILD_RUST_BINDING=ON \
  -DBUILD_LANGUAGE_SERVER=OFF -DBUILD_LANGUAGE_SERVER_EXTENSION=OFF \
  -DPython3_EXECUTABLE=/usr/bin/python3 \
  -DZR_VM_LIBFFI_INCLUDE_DIR=/usr/include/x86_64-linux-gnu \
  -DZR_VM_LIBFFI_LIBRARY=/usr/lib/x86_64-linux-gnu/libffi.so
cmake --build /workspace/cargo-targets/zr-gd-m5/release -j1 \
  --target zr_swarm zr_vm_cli_executable zrgame_plugins zrgame_native_tests
export ZR_VM_NATIVE_PATH=/workspace/cargo-targets/zr-gd-m5/release/demos/swarm_arena/native
/workspace/cargo-targets/zr-gd-m5/release/bin/zr_swarm \
  --project demos/swarm_arena/game/swarm_arena.zrp --host-api session \
  --expect-hash 552988638 --out /workspace/cargo-targets/zr-gd-m5/session-smoke
```

`--host-api library` remains the default, including the C lane. Session mode
supports DOD source execution, requires the existing descriptor plugins on
`ZR_VM_NATIVE_PATH`, and defaults to slack GC. Other session GC policies and
`--gc-minor-interval` are rejected. A build without the shared binding keeps
the library/C host paths and reports an explicit error for session mode.

`--instruction-budget` sets a finite frame cap, default 100,000,000 and range
0–1,000,000,000. Zero and one are useful termination checks. Every frame calls
`ProjectSession_CallModuleExportWithBudget("game", "frameStep", ...)` once;
the additive script export executes tick and bulk render preparation together.
The native backend completion happens afterwards. Termination exits 2 and
preserves measured usage without printing `SWARM_OK`. It does not undo the
partially executed frame.

After freeing argument/result handles and completing the backend, the loop
computes `slack = max(0, 16667 - elapsed_frame_micros)`. Positive slack is passed
unchanged to `ProjectSession_GcStep`. With zero slack, no step is requested.
`--gc-budget-us` initializes runtime pause/remark budgets; the session API
subsequently changes the collector's pause allowance to the supplied slack.
These cooperative APIs provide no strict wall-clock pause guarantee.

## Artifacts and measured results

Session mode writes `session-frames.csv` and `session.json`. Its artifacts are
separate from the existing library/C `frames.csv` and perf summary schema.
The CSV records frame/pass, state hash, sprite count, all five call usage
fields, termination, frame duration, GC slack/request/pause/root observations
and completion status. Failed calls retain a row. The JSON includes totals,
completion counts, the original failed operation and rewind progress; failures
replace previous successful summaries when reusing an output directory.
The CSV hash is the rolling tick hash. Summary and rewind hashes use the
existing `fullHash` export, which includes the additional position hash.

`executedInstructions`, `elapsedMicros`, `gcMicros`, `peakHeapBytes` and
`nativeCalls` come directly from the budgeted call usage. Explicit post-frame
GC pauses are recorded separately. Peak heap is the maximum live requested
memory observed by the VM allocator, including preexisting allocations; it
does not measure native allocations outside that allocator. Timing below is
descriptive, with no performance threshold claim.

## Rewind blocker and reproduction

```sh
python3 -I demos/swarm_arena/tools/run_session.py --check rewind \
  --host /workspace/cargo-targets/zr-gd-m5/release/bin/zr_swarm \
  --cli /workspace/cargo-targets/zr-gd-m5/release/bin/zr_vm_cli \
  --native-dir "$ZR_VM_NATIVE_PATH" \
  --out /workspace/cargo-targets/zr-gd-m5/rewind-new
```

The host checkpoints after completed frame 600, retains no live binding Value
roots, runs to frame 720 and rolls back. A successful implementation must first
restore the frame-600 full hash, then replay frames 601–720, checking every
frame hash and the final full hash. The first-pass hashes observed here were
997232702 at 600 and 810114730 at 720. The API returned OK for checkpoint and
rollback, then the restored hash read failed:

```text
SWARM_ERROR session.fullHash status=7 failed to call module export game.fullHash: GET_MEMBER: missing member 'fullHash'
```

Cleanup separately reported missing member `rendered`. The host preserves
`failure_operation=fullHash`, `binding_status=7`, `replayed_frames=0` and
`rewind.equal=false`. It exits 2; the runner exits 1. No game rollback equality
is claimed. The 720-frame instruction table remains usable evidence of the
completed first pass.

The additive standalone probe removes the game, renderer, budget and GC-step
loop to isolate retained state:

```sh
python3 -I demos/swarm_arena/tools/probe_session_rollback.py \
  --binding /workspace/cargo-targets/zr-gd-m5/release/lib/libzr_vm_rust_binding.so \
  --out /workspace/cargo-targets/zr-gd-m5/rollback-probe-new
```

Its scalar and `Array<int>` controls restore 600 and replay to 720. A small
script `Counter` class gets OK for checkpoint/rollback, then fails the first
post-rollback `counter.read()` with:

```text
CallBinding link error: stale-generation (token=0x03000001, instruction=2)
```

This establishes a class-call failure after rollback in the supplied engine;
it does not establish the exact cause of both diagnostics. Investigation can
start at `session_checkpoint_restore.c`'s prototype/function/call-site restore
and `call_binding_member.c`'s binding validation. No engine change, verifier
disable, alternative state serialization or golden regeneration was used.
The failing rewind remains an explicit probe and is not registered as a passing
or expected-failure CTest.
