# GD-M1: OpenGL 3.3 and window input

The host supports `--render gl`, `--headless`, `--snapshot 60,120` and
window-only `--interactive` WASD input. The default remains `--render null`.
CLI drive continues to use null rendering. No engine sources change.

## Build and headless verification

GLFW 3.4 and the generated glad 2.0.8 GL 3.3 core loader are vendored with
licenses under `third_party/`. `ZR_SWARM_GL=ON` tries Linux X11 graphics and
falls back to null when the headers, libraries or vendored sources are absent.
Use `ZR_SWARM_GL=OFF` to explicitly build without graphics. Xvfb is required
only for the graphics CTest. Missing prerequisites produce CTest **Skipped**
(exit 77); rendering, shader and image mismatches fail the test.

On the provisioned workstation, use the existing extracted packages. Do not
use apt-get or change system packages/configuration. The demo automatically
searches `build/local-tools/debs-extracted/usr`; another private prefix can be
selected with `ZR_SWARM_DEPS_PREFIX`, or standard `CMAKE_PREFIX_PATH` settings.
No graphics search flags propagate into engine targets.

```sh
mkdir -p /workspace/zr_vm-review/evidence/gd-m1-20261029/local/runtime
export TMPDIR=/workspace/zr_vm-review/evidence/gd-m1-20261029/local/runtime
cmake -S . -B /workspace/cargo-targets/zr-gd-m1/release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DZR_VM_BUILD_DEMOS=ON -DBUILD_TESTS=ON \
  -DBUILD_LANGUAGE_SERVER=OFF -DBUILD_LANGUAGE_SERVER_EXTENSION=OFF \
  -DBUILD_RUST_BINDING=OFF -DPython3_EXECUTABLE=/usr/bin/python3 \
  -DZR_VM_LIBFFI_INCLUDE_DIR=/usr/include/x86_64-linux-gnu \
  -DZR_VM_LIBFFI_LIBRARY=/usr/lib/x86_64-linux-gnu/libffi.so \
  -DZR_SWARM_TEST_ARTIFACT_DIR=/workspace/zr_vm-review/evidence/gd-m1-20261029/local
cmake --build /workspace/cargo-targets/zr-gd-m1/release -j 1 \
  --target zr_swarm zrgame_gl_tests zrgame_native_tests zrgame_plugins zr_vm_cli_executable
ctest --test-dir /workspace/cargo-targets/zr-gd-m1/release \
  -R '^demo_gl_xvfb$' -j 1 --output-on-failure
```

The runner starts its own Xvfb with automatic display allocation, TCP transport
and a private Xauthority cookie. It sets `LIBGL_ALWAYS_SOFTWARE=1`, llvmpipe,
one raster worker, and cache/temp directories under its explicit output path.
It neither requires an inherited `DISPLAY` nor writes test artifacts into the
source tree. The native fixture checks camera translation, packed RGBA, alpha,
rotation, clipping, text, empty frames and readback after swapping. Optional
XTEST runtime support additionally drives actual WASD, opposing/diagonal keys,
key releases and Escape through a visible GLFW window.

Both DOD and C run the 120-frame smoke scenario with hash **552988638**.
Their GL images are compared and the C image is checked against
`goldens/gl33-smoke.ppm`; the native fixture uses `goldens/gl33-fixture.ppm`.
Every pixel matches only if **all** RGB channel differences are at most **2**;
at least **99.5%** of pixels must match. The comparator includes controls at
the 99.5% boundary. `images-gl33.json` records baseline provenance and checksums.
Goldens are never regenerated by CTest. For a candidate capture, explicitly
run `tools/run_gl.py --capture` with the same executable/output arguments,
inspect it and review geometry/coverage before replacing a golden.

## Rendering and input conventions

Sprites remain the existing 20-byte `(x,y,size,rotation,0xRRGGBBAA)` records.
The GL path uses one unit quad, an orphaned streaming instance VBO plus one
`glBufferSubData`, and one `glDrawArraysInstanced` per frame. HUD glyph pixels
join the same instance stream. World quads rotate clockwise in the screen's
downward y axis. The camera retains the existing 1280x720 world view; the
offscreen RGBA8 image is always 640x360, nearest-filtered, without MSAA, sRGB
conversion or dithering. The background is RGB `(16,20,28)`; standard source
alpha blending preserves submission order. P6 PPM and miniz PNG snapshots are
top-to-bottom, derived from `glReadPixels` of that framebuffer. Presentation scales the
image to the actual window framebuffer, including display scaling.

Windowed runs advance at most 60 fixed simulation steps per second; headless
runs are uncapped. WASD moves 240 world units/second with normalized diagonals,
clamped to `[0,4095]`. It replaces bot lookup and automatic dodge only when
`--interactive` is supplied. Auto-fire stays active; the camera follows the
player. An unfocused window receives zero movement. Escape or window close
finishes normally, reporting the actual completed frame count. Escape is polled
once per frame: keep it pressed until the window closes; a press and release
entirely between polls can be missed. `--interactive`
with soft/null/headless rendering fails clearly. Snapshot I/O errors also fail
without a successful summary. Frame-list snapshots use one-based completed
frame numbers and write `frame-000060.ppm`, `frame-000120.ppm`, etc. under
`--out`. A `.ppm`/`.png` path instead captures the last completed frame to that file.
`gfx.snapshot("")` returns the FNV-1a hash (low 31 bits) of top-to-bottom RGBA8
pixels on GL. Null keeps its existing batch hash and ignores snapshot paths.
