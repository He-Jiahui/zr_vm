# 04.02 Dynamic Meta-Tail Fallback Window

## Scope

- Fixes fallback-window sizing after a dynamic callable is rewritten to its
  `@call` function and frame reuse declines.
- Affects core dispatch and the parser-to-runtime call pipeline regression.
- Does not complete the broader 04.02 transfer-plan or return-forwarding work.

## Baseline

- The ordinary dynamic-call control returned `347`.
- Before the fix, the separate `DYN_TAIL_CALL` graph reached the tail fallback,
  then hit the integer `ADD` operand type assertion at
  `execution_dispatch.c:6816`. The original process remained blocked after the
  assertion output; root terminated that owned process. It did not exit
  naturally.
- The focused MSVC target build completed 11/11 edges before the fix.
- The test-only RED build used the same VsDevCmd and D-drive TMP/TEMP setup
  as the final build below, with only zr_vm_call_binding_pipeline_test as
  the target; the direct command was the same pipeline executable below.
  The observed output first printed ordinary dynamic-call control passed: 347,
  then the tail assertion. Final direct exit 1 was the root-owned forced
  termination after the assertion blocked.

## Results

- Pre-fix RED reached the intended runtime path only after the ordinary
  `347` control had passed.
- The fallback helper now derives the copied value count from the live span
  between the callable slot and `state->stackTop`, preserving the slot inserted
  for the meta receiver and all original arguments.
- The existing helper remains in `execution_dispatch.c` because it also owns
  staging-copy and stack-anchor restoration; extracting only the span
  calculation would create a weaker cross-file boundary.
- Post-fix MSVC target build passed: 708/708 build edges, exit 0.
- `zr_vm_call_binding_pipeline_test` passed: 18 tests, 0 failures, 0 ignored
  (3.17 seconds).
- `zr_vm_tail_reuse_callinfo_reset_test` passed: 4/4 (1.11 seconds).
- Registered CTest passed: 2/2. `call_binding_pipeline` took 2.96 seconds,
  `ssa_call_return_tail` took 0.70 seconds, and the CTest command took 6.27
  seconds total.

## Acceptance Decision

- Accepted for this bounded fallback-window regression: the direct tail-call
  case now preserves the `@call` receiver and final sentinel after frame reuse
  declines, and the adjacent tail-reuse and registered SSA call/return/tail
  gates pass.
- The 04.02 milestone remains open after this bounded fallback-window slice.

Only MSVC Debug gates were run for this bounded fix; GCC, Clang, and NDEBUG
were not run.
