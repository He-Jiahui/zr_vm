# 10-S5J / 12-S5I dynamic-dependency type-layout root

Time: 2026-06-30 16:25:31 +08:00

## Scope

This slice accepts a narrow current-module carrier for preserving generated type-layout metadata during opt-in AOT C code stripping.

`dynamicDependencyTypeLayoutId` in function decorator metadata is interpreted as a uint32 generated type-layout id. The owning function may still be trimmed; the generated `SZrTypeLayout` descriptor and code-registration `typeLayouts[]` entry are preserved.

Out of scope: TypeDef/TypeSpec token dependencies, field dependencies, cross-module annotations, non-method member token dependency rules, `@dynamically_accessed` dataflow, warning promotion/per-warning suppression, unannotated reflection warnings, type/member DESCRIPTION promotion, and complete metadata sweep.

## RED

Added `test_aot_c_code_stripping_preserves_dynamic_dependency_type_layout_metadata`.

Before implementation, WSL GCC focused `zr_vm_aot_c_code_stripping_test` ran 6 tests with 1 failure. The new fixture failed with `Expected Non-NULL` because `ZrTypeLayout_2` was removed together with the otherwise unreachable function that originally referenced it.

## Implementation

- `backend_aot_c_emitter.c` now collects `dynamicDependencyTypeLayoutId` roots before function-table filtering and writes `code_stripping.annotationTypeLayoutRoots` / `code_stripping.annotationTypeLayoutRoot[index]` markers.
- `backend_aot_c_type_layouts.{h,c}` now exposes `backend_aot_c_type_layout_collect_dynamic_dependency_roots(...)`.
- Referenced type-layout count, payload bytes, generated bytes, declaration emission, layout index space, GC descriptor index space, GC descriptor table emission, and registration table emission now accept the root set.
- Root-only type layouts are emitted after frame-referenced layouts, and duplicate frame/root references are ignored.
- Registration table entries for rooted type-layout ids resolve to `&ZrTypeLayout_<id>` even when no retained function frame still references the layout.
