# Plan 03 Task 6.6: Query Diagnostic Disposition

## Goal

Make every no-fix diagnostic generated by the canonical semantic-query
materializer and generic compiler-error persistence bridge carry an explicit
typed reason.

## Contract

- `unreachable_code` publishes `UNSAFE_EDIT`; deleting code is not an
  intent-preserving automatic repair.
- Numeric overflow and all array bounds/index type diagnostics publish
  `REQUIRES_USER_DECISION`.
- A generic `compiler_error` bridge fact publishes `INSUFFICIENT_CONTEXT`
  because it has no structured producer contract beyond message and range.
- Definite-assignment diagnostics retain their existing typed placeholder fix.
- Message, code, and suggestion text do not select or reconstruct an edit.

## Implementation

The query materializer sets a typed reason immediately after constructing each
unreachable, overflow, or array diagnostic and frees the diagnostic if the
disposition cannot be recorded. The generic compiler bridge applies the same
cleanup-safe rule before appending its persistent fact.

Existing compiler/query end-to-end tests now assert exact reasons for two
unreachable paths, overflow, definite and possible bounds, non-integer index,
and generic compiler error publication.

## Verification

On the byte-equivalent `0c1ca3f57659 + 3 code/test overlays` snapshot, WSL GCC
11.4 and Clang 14 directly report 46/46 for compiler semantic-query
diagnostics. MSVC 19.44 reports the same 46/46. Every direct sequence exits
zero.
