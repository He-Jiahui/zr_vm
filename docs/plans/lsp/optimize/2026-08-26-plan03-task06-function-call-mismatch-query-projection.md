# Plan 03 Task 6.12: Function Call Mismatch Query Projection

## Goal

Make a single resolved free-function candidate publish its argument type
mismatch as the same canonical descriptor `2011` fact used by assignment,
initializer, and return compatibility. The language server must project that
query fact without rebuilding a diagnostic from compiler text or inferred type
names.

## Contract

- The overload scorer identifies the exact incompatible parameter index only
  after generic binding and argument mapping have succeeded.
- A detailed mismatch is published only for one resolved free-function
  candidate and a value-parameter type incompatibility. Generic binding,
  overload ambiguity, ownership, arity, and `ref`/`out` failures retain their
  existing diagnostics.
- The primary range is the mapped source argument. Related information points
  to the declared parameter type range. The typed placeholder fix comes from
  the parser diagnostic builder.
- Named and positional argument lookup uses AST argument/parameter identity;
  it does not compare source text to infer types or targets.
- `SemanticAnalyzer_ConsumeCompilerErrorDiagnostic` publishes the current
  compiler error into persistent query facts and projects that query. If fact
  publication fails, it preserves the compiler error and fails closed.

## Implementation

`score_function_overload_candidate` now returns the first exact incompatible
parameter index alongside its existing ownership classification. The overload
resolver invokes a dedicated call-diagnostic module only for the one-candidate
case, while all multi-candidate and non-type failures preserve the prior
overload contract.

The new call-diagnostic module maps that parameter index back to the argument
AST node and the declaration parameter. It calls the shared detailed type-error
builder with both ranges, so descriptor id, code, cause, suggestion, related
information, and typed fix are generated by parser/compiler policy.

The LSP compiler-error consumer no longer calls
`Diagnostic_FromStructured` or `SemanticAnalyzer_AddDiagnostic` directly. It
publishes the compiler error through the semantic-query bridge and clears the
transient error only after successful publication. Source-contract coverage
prevents those direct producer paths from returning.

## Verification

The initial RED observed no precise canonical call-argument fact and exposed
broad fallback diagnostics. A separate receiver-method RED also showed a
whole-argument-list mismatch and an analyzer-owned duplicate; that producer is
in the currently frozen receiver inference path and is intentionally not
claimed by this milestone.

On one fixed 11-path source overlay, GCC 11.4, Clang 14, and MSVC 19.44 each
directly passed:

- compiler semantic query diagnostics: `49/49`;
- semantic query diagnostic disposition: `8/8`;
- LSP semantic query diagnostics, including the precise free-function call
  argument case;
- LSP source contracts;
- type inference: `123/123`;
- compiler integration: `127/127`;
- semantic analyzer and union-pattern diagnostic focused regressions;
- stdio structured-diagnostic fix smoke, including exact primary/related
  ranges and the typed placeholder fix.
