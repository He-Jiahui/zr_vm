## Native Storage

`TokenStream` owns source names, source bytes and decoded token text. Each source
record receives a stream-local, nonzero `TokenSourceId`; zero means no source.
`TokenText` is a bounded `(sourceId, offset, length)` slice. Empty decoded strings
are valid slices and are different from an absent descriptor.

The builder has separate all-node and root-node vectors. A group owns its child
pointer vector, but its children remain in the all-node arena for destruction.
`Count`/`At` expose only top-level roots. This avoids duplicate traversal and
double-free when groups import child streams. Group cloning and token cursor
flattening use explicit native stacks instead of recursive C calls.

Each leaf stores its original spelling separately from decoded semantics.
Numeric native values do not require an additional decoded spelling. Identifiers
and string/template payloads do require owned decoded text. Punctuation is one
legal codepoint plus `Alone`/`Joint`; groups carry delimiter kinds and distinct
opening/closing spans. Leading/trailing trivia belongs to a tree; empty groups
and comment-only streams need explicit unattached-trivia views.

`Seal` prevents further mutation and snapshots the stream's resource policy, so
retained immutable data does not borrow a stack budget. `Release` frees every
arena node once, then source storage, vectors and the retained context table.
Callers must release the stream before destroying its VM global allocator.

## Cursor Contracts

Splitting `>>` must deliver the pending second `>` before an already-prefetched
following token, without dropping that token or re-reading it. Checkpoints keep
all three states coherent: stream index, pending punctuation and cached
lookahead. Source-text speculation also preserves split/lookahead flags.

Joint spacing controls compound punctuation even when the pieces came from
different source records or hygiene contexts. Synthetic compound display bytes

## AST and GC Lifetime

Each parsed node retains a reference to `SZrAstOwnership`. The lexer initially
owns another reference. The shared owner retains the native input stream and
deduplicates VM string roots by pointer, covering semantic strings, synthesized
parser names and source names. A detached statement or expression therefore
outlives `State_Free` and the caller's stream/context references.

AST fields contain raw VM string pointers. An independent `GcRootHandle` keeps
each string alive, while physical pinning keeps its storage stable across moving
collections. A root is not a pin, and an escape marker is not a root. Multiple
AST owners use independent handles so freeing them out of order is valid. Pin
metadata does not create a permanent strong root; ordinary GC may reclaim the
object after all real roots are released. VM state/global lifetime remains a
caller precondition.

`Ast_Free` releases children before the node's owner reference. Replaced wrapper
nodes use the same destructor after detaching transferred children, rather than
bypassing common ownership cleanup with raw free. Public immutable syntax clones

## Private Source Projection

[`parser_source_projection.c`](../../zr_vm_parser/src/zr_vm_parser/parser/parser_source_projection.c)
and its private header separate source-name materialization from cursor reads.
`SZrParserSourceNameCache` is an open-addressed, power-of-two table keyed by a
nonzero stream-local `sourceId`, not filename spelling or AST identity. It lives
inside private `SZrTokenSourceState`; that cache-only repair does not extend the
public AST/FileRange ABI. The separate range work below now extends `FileRange`;
its R17 focused GREEN still leaves the wider provenance/platform work unaccepted.
`CacheSpan` validates the original Span, copies the stream's counted source name
into a VM string once per sourceId, and reuses that entry on later visits.

`token_source.c` first flattens the sealed stream, then prewarms names for every
cursor item and the stored EOS Span. Only after both steps succeed does it
publish `lexer->tokenStream` and `tokenSourceState`. Failure destroys the private
cache/cursor storage and releases its stream reference without publishing a
partially usable cursor. Normal lexer Init reports the failure before reading
the first token. This is not a new global OOM or whole-initialization budget
rollback guarantee.

`FindName` and `TokenSource_SourceName` only read the prepared table. Parser
`SourceName` and `CurrentLocation` select that cached name and copy the current
original Span's offsets/line/column without changing `lexer->sourceName` or
token origin. Both parser location readers delegate here for stream input and
inherited-span text. Embedded-source Init selects the parent's name for its
actual origin, preserving the existing shared owner. Missing/invalid stream
origins fail closed with parser fatal/error and lexical error flags; they do
not silently relabel a token with the entry name. Source selection itself is
allocation-free after initialization, including during repeated lookahead;
this does not claim that all token materialization is allocation-free.

The cache table borrows its VM strings from the existing `SZrAstOwnership`.
Table capacity is charged through `Ownership_Allocate`; string bytes and
root/slot storage use the existing budgeted `Lexer_CreateString` transaction,
which roots and pins retained strings. Cursor destruction frees the native
table, not the AST owner's roots. Retained AST references therefore keep those
strings and the input stream alive after parser/external reference release.
Owner teardown releases roots and the stream; VM state/global lifetime remains
a precondition. Different owners do not share a new global cache.

An empty source-constructed stream still prewarms its valid EOS source name.
A manually created source-less empty stream with EOS, no lexical error and
invalid sourceId is the narrow exception: it needs no cache entry and projects
an empty `0..0` range at line1/column1 with NULL source. A valid source record
whose name length is zero is different: its non-NULL native empty name is
materialized as an empty VM string, not treated as a missing source or replaced
by the entry name. Other invalid/missing origins are errors.

### Diagnostic Evidence Publication

The nine production paths comprise the existing range reader, fact dispatcher
and owner modules plus five new private files, not nine new public APIs.
[`parser_range_evidence.c/.h`](../../zr_vm_parser/src/zr_vm_parser/parser/parser_range_evidence.h)
expose pure `Describe`/`AnchorAt` reads of the validated owner ledger. A keyless
legacy or explicitly PARTIAL range describes NONE; malformed known evidence
fails. SOURCE has one physical anchor; INTERVAL describes canonical first/last
native ordinals. A fresh interval handle is not a new identity. These reads do
not allocate, charge resources, rewrite token Spans or manufacture an envelope.

[`semantic_facts.c`](../../zr_vm_parser/src/zr_vm_parser/semantic/semantic_facts.c)
dispatches any nonzero `ownerKey` or `evidenceIndex` to
[`semantic_diagnostic_evidence.c/.h`](../../zr_vm_parser/src/zr_vm_parser/semantic/semantic_diagnostic_evidence.h).
That path requires a live `fact.node->ownership` and complete validated evidence;
it does not silently downgrade a missing owner to the legacy path. Keyless legacy
diagnostics retain their previous copy/dedup behavior, including the node-NULL
unknown-range control. Known-evidence dedup compares owner, origin, evidence kind,
canonical interval ordinals (or SOURCE physical coordinates), code and message;
it does not use display names or the allocated interval index as native identity.

For a new fact, the private publisher preserves the caller's primary location,
all caller-supplied related labels and fixes. For COMPOSITE evidence it appends
each missing unique physical fragment in native order, excluding the primary and
already labeled fragments. Physical equality includes origin and both complete
offset/line/column endpoints. It does not collapse distinct nested intervals
merely because their first anchor is equal.

Publication stages a replacement related array, fixes, optional expanded fact
array and string inventory under one owner-budget transaction. Checked sizes,
comparisons, ledger iteration and pin dedup charge FUEL; native array/pin storage
charges HEAP, new pins charge AGGREGATE_COUNT, and a new fact charges
DIAGNOSTIC_COUNT. Only after all fallible preparation and budget commit does it
link pins and publish the fact through allocation-free operations. A failure
discards staged arrays and prepared pins before aborting: existing payloads,
owner roots/pin refs and budget usage remain unchanged, while the budget's
exceeded-resource report may record the rejected limit for the caller.

[`parser_ownership_strings.c/.h`](../../zr_vm_parser/src/zr_vm_parser/parser/parser_ownership_strings.h)
keeps exact-size native pin blocks separate from the pre-existing owner string
table. Prepare requires an independent empty output slot, an active transaction
on that same live owner's current budget, and live unchanged inputs; it never
commits or aborts the caller's transaction. It deduplicates against owner strings,
published blocks and earlier inputs, pins only missing strings, and releases its
own partial pins on failure. Apply transfers a prepared block once, without
allocation; Discard is only for an unpublished same-owner block. Final owner
release unpins these blocks before releasing existing string roots, range
evidence and the retained TokenStream. The semantic context frees diagnostic
arrays, not the owner; node/owner references remain borrowed. Pins can therefore
outlive a diagnostic reset until owner release, not until an arbitrary GC cycle.
`DetachBudget` copies a borrowed lexer budget into owner fallback storage before
the cursor can disappear, so a surviving AST does not retain a stack-budget

## Callable Binding Context

Function declarations compare names in the item namespace. Callable values
compare names in the local namespace, including aliases, lambdas, and annotated
function parameters. Registration rejects a duplicate only within the same
normalized context. Equal signatures in different definition contexts remain
distinct. The old name-only lookup and callable-value registration APIs use
the root context; compiler paths that have an identifier use the explicit
`WithContext` entry points.

`type_environment_callable_lookup.c` owns callable candidate lookup, context
comparison, and signature comparison. For each lexical environment, lookup
checks whether a variable with the same normalized local identity is present.
Such a variable hides function declarations and stops traversal to parent
environments. A variable in another definition context does not hide the
requested function. Callable metadata for that local value remains eligible.
Overload sets preserve this distinction before the existing overload scorer
checks argument types, ownership, generic arguments, and ambiguity.

An alias has two independent identities. Its initializer identifier chooses
the source signature using its own context. The declaration pattern supplies
the destination context used to register the alias. Copying the source context
onto the destination would bind a different local. External callable aliases
likewise retain the destination's context while preserving their verified
structural signature identity.

Identifier inference, call inference, runtime call lowering, and compile-time
fallback lookup pass the target identifier's context. Named/default arguments
are arranged from the declaration selected by overload resolution. Scanning
the script for the first matching spelling can select another context's
parameter names even when overload resolution chose the correct signature.

`compiler_register_typed_callable_annotation` registers fixed function-type
annotations for parameters and local variables. This includes a local whose
initializer is a call returning a function value. Existing equivalent callable
metadata is reused only when context, return type, parameter types, and passing
modes agree. These values receive `TYPED_FUNCTION` call contracts and reject
incompatible arguments through the ordinary overload resolver. Canonical
function-value fallback also queries its binding with the target context.

Typed local metadata reads contexts from the compiler's parallel
`localBindingIdentities` table. A runtime slot row contains no context pointer;
the final row stores the already-resolved type and semantic identities. Looking
up its type by spelling alone can report an unrelated same-name string for an
integer slot even when execution uses the correct slot.

The focused alias suite has lookup, shadowing, source/destination alias,
inference, named argument, annotated callable, and local metadata cases. Runtime
companions execute distinct same-name functions and aliases; negative cases
reject invalid callable arguments in root and definition contexts. It remains
separate from the native-token closure and provenance suites, and does not
waive type-value alias or complete compiler acceptance.

## Type-Value Alias Scope

The outer compiler scope retains its aliases for post-lowering metadata and

## Nominal Declaration Lookup

`compiler_type_declaration` owns source declaration lookup formerly embedded
in `compile_expression_types.c`. It covers the existing struct, class,
interface, enum, union and extern delegate cases. It searches the script's
direct declarations first, then declarations in extern blocks, preserving the
existing order. The compiler's retained script AST owns the returned node.

`find_type_declaration_with_context` accepts spelling and a syntax context.
Both the requested and declared identifiers normalize in the item namespace:
opaque marks distinguish definitions; transparent and semi-opaque item marks
retain root compatibility. Invalid contexts, absent names, missing arrays and
non-script roots return NULL. The helper neither allocates nor modifies AST or
compiler state. `find_type_declaration` is the root-context compatibility entry.
It cannot select an opaque definition merely because its spelling matches.

The independent nominal fixture parses two same-spelling declarations and
first verifies ordinary registration produces a real canonical nominal and
type symbol. Four functional REDs then identify lost registration context,
root-name publication, collapsed declaration identities and name-only lookup
selecting the first opaque declaration. The new lookup module repairs the last
path. Context-qualified type environment registration below repairs the three
direct registration failures. AST annotation canonical conversion, prototype
lookup and construction still require separate repairs; these helpers do not
establish complete nominal hygiene.

Rust's opaque versus opaque-and-semiopaque projections are visible in
`lua/rust/compiler/rustc_span/src/hygiene.rs:449-456`. CPython's class visitor in
`lua/cpython/Python/symtable.c:1944-1971` separately records the local name and
opens a block keyed by the declaration AST. The latter is a declaration
identity/storage precedent, not a claim that Python supplies macro hygiene.

## Nominal Type Environment Binding

`SZrTypeEnvironment.namedTypeBindings` owns an array of `SZrNamedTypeBinding`
records. A record borrows the spelling, declaration AST and syntax context,
and stores the published SymbolId and TypeId. Environment construction and
destruction initialize/free the backing array. As with existing variable
bindings, callers must retain the enclosing AST/context owner; semantic symbol
publication also retains its context table through the existing semantic API.

`RegisterTypeWithContext` deduplicates spelling plus normalized item context
in the current environment. `RegisterTypeDeclaration` derives the context from
the actual named declaration; `RegisterType` remains a root wrapper.
`FindTypeBindingWithContext` searches the current environment in reverse order
and then its parents. `LookupTypeWithContext` uses that identity and consults
the legacy `typeNames` table only for item-root requests. The old `LookupType`
entry is a root query. Opaque declarations therefore do not populate or leak
through the name-only table; mixed-site items retain root compatibility.

Root declarations keep the existing name-based canonical projection. Marked
declarations reserve a real semantic SymbolId and use it as the canonical
nominal `definitionToken`, then publish a canonical semantic type and the
context-qualified symbol. Same-spelling opaque/root registrations have distinct
IDs without changing displayed names. Repeated registration reuses the binding.
This is snapshot-local identity, not serialized macro/module identity.

Invalid arguments or contexts return false before publication. Canonical and
symbol failures propagate false, but the underlying array Push and semantic
interner still lack complete OOM rollback. This change adds no transaction
guarantee. The independent eight-case native test passes after the registration
repair. Six companions for order, repeat, context lookup, mixed-site items,
parent shadowing and invalid contexts expand it to 14 passing cases.
Inferred-type conversion still reconstructs nominal types from spelling, and
the remaining prototype/construction paths are explicitly unaccepted.

## Nominal Annotation Visibility

`type_inference_type_visibility.c` owns the explicit-binding predicate formerly
embedded in `type_inference_core.c`. Its contextual entry accepts a spelling
and the annotation's actual syntax context; the existing name-only entry is
a root wrapper. Invalid contexts return false before lookup. Local aliases and
named environment bindings use context-qualified lookup. Source declarations
use the shared `compiler_type_declaration` helper, eliminating a second,
context-blind declaration scanner in type inference. The two remaining
name-only declaration consumers explicitly retain root lookup; this extraction
does not make their construction paths context-aware.

The identifier and generic-base branches of AST type conversion pass their
own identifiers' syntax contexts to this predicate. An opaque definition
cannot see a root-only declaration by spelling, and a root request cannot see
an opaque-only declaration. A matching environment binding remains usable
without `scriptAst`; a matching source declaration remains usable before
environment registration. Call-site and mixed-site item requests keep their
root-compatible behavior. Generic arguments retain the existing recursive
conversion; this change addresses the nominal base's visibility only.

The module preserves existing `zr` module bootstrap, qualified registered
prototype lookup, and generic-parameter availability. Those paths still rely
on name-based metadata and are not a complete module or generic-parameter
hygiene contract. Builtins and reserved decorator pseudo-types retain their
existing conversion exceptions. The predicate does not own AST/context data
or change prototype registration; module bootstrap may still load metadata.

The initial annotation extension ran 20 cases with 17 PASS and three genuine
visibility failures. After the repair, all 20 passed. Mixed-site, invalid
context and five generic-base companions expand the target to 27 passing
cases with zero ignored. These assertions inspect visibility and successful
conversion, not equality with the registered opaque canonical TypeId.
At that checkpoint, inferred nominal identity still came from spelling alone.
The next support repair below addresses that projection; prototype/construction
identity and full M1 acceptance remain separate, open work.

## Inferred Nominal Identity

`SZrInferredType.nominalDefinitionToken` carries the existing canonical nominal
definition key through the compatibility representation. Zero retains the
legacy name-based identity. A nonzero token is the declaration's already
reserved SymbolId within the current semantic snapshot, not an AST address,
syntax-context hash, new TypeId or serialized identity. It must not be moved
between semantic snapshots or module identity domains. The field owns no
resources; Init/InitFull and Free clear it, and Copy preserves it recursively.

Canonical nominal registration copies the node's definition token into its
semantic record's inferred representation. Shared inferred equality and named
object compatibility compare the token before treating equal spellings as
equal types. Nullable widening cannot make distinct declarations compatible;
the existing unnamed dynamic-object destination remains unchanged.

`type_inference_nominal_identity.c` resolves a marked source annotation through
its context-qualified named binding. If the matching declaration is forward
referenced, the helper registers it through the normal type environment API
before retrieving its canonical key. The enclosing AST, context table and
semantic snapshot retain their existing ownership requirements. Root-compatible
annotations keep their previous projection. Qualified prototypes and generic
parameters without a matching nominal binding keep their existing behavior;
this is not a new generic-parameter or module hygiene guarantee. A type
environment without a semantic context cannot mint canonical identity.

The identifier and generic-base conversion branches call this shared helper.
Marked annotations no longer publish a second root named type during semantic
registration. The canonical adapter threads the token into nominal interning
for both ordinary types and generic definitions, while generic arguments and
array/ref/owner/nullable wrappers use the existing recursive projection. A
nonzero nominal token on a primitive or unnamed type is rejected. Explicit
generic name bindings cannot capture an already resolved marked nominal type.

The initial 38-case fixture has 28 PASS and ten functional REDs: canonical
annotation identity, semantic-record round trip, inferred equality and
compatibility, nullable compatibility, generic base identity, ref pointee,
array element, forward binding publication and deep-copy preservation.
The corrected six-target shared-ABI build completes successfully, and all
38 nominal cases pass. Canonical graph 19/19, type inference 125/125, canonical
consumers 21/21, semantic symbols 42/42 and display 29/29 also pass, with zero
ignored cases. Nine boundary companions expand nominal coverage to 47/47:
initialization/free, invalid primitive/unnamed tokens, generic-binding capture,
legacy unmarked binding behavior, same-identity nullable/dynamic compatibility,
mixed-site identity, repeated publication, nullable projection and nested
generic arguments. These companions require no further production change.
No prototype/construction, artifact serialization, cross-snapshot identity or
OOM transaction acceptance is inferred from this change.

Rust stores `TyKind::Adt(AdtDef, GenericArgs)` in
`lua/rust/compiler/rustc_type_ir/src/ty_kind.rs:84-91`; `AdtDefData` and its
equality in `lua/rust/compiler/rustc_middle/src/ty/adt.rs:100-134` use DefId,

`lua/mono/mono/metadata/class.c:2843-2887` resolves a metadata token within its

ZR reuses its current nominal definition key; it does not import either
runtime's metadata model or claim stable binary macro identity.

## Nominal Prototype Visibility

Generic definition and specialization identity have a separate support contract
and regression checkpoint in [Macro Generic Type Identity](macro-generic-type-identity.md).

`compiler_type_declaration_item_context` is the shared source-declaration
context extractor. It validates the identifier and normalizes the ITEM
namespace. The top-level duplicate guard compares that context as well as
spelling, so Root and definition-site declarations may coexist while two
different declarations in the same normalized context remain duplicates.
Repeated publication of the same AST declaration remains idempotent.
Failed normalization is not context inequality: the extractor rejects an
invalid result, and the duplicate guard reports a compiler error and blocks
publication if either declaration cannot be normalized.

The ordinary inference prototype query is intentionally a Root query. Both
the exact and local registry scans, including the in-progress current type,
reject source prototypes whose declaration context is not Root. Imported
metadata-only stubs retain ordinary lookup and existing source-over-stub
precedence. No imported AST pointer is added: temporary source imports and
restored compile-time imports do not share the local prototype lifetime.

`type_inference_find_nominal_prototype` handles full inferred types. A zero
definition token uses ordinary Root lookup. A nonzero token resolves a TYPE
symbol in the active type environment's semantic snapshot and matches the
retained local declaration, requested type name and normalized item context.
Protocol queries use this path. Missing symbols, wrong symbol kinds, missing
declarations or a missing matching prototype fail closed; they cannot borrow
the protocol mask of a same-name Root type or imported stub. This helper owns
no prototype/declaration storage and introduces no public structure field or
new identity. Context normalization uses the existing budgeted machinery.

The separate prototype fixture establishes a Root prerequisite and same-context
duplicate/import compatibility before testing contextual lookup and protocol
isolation. Its corrected 17-case native RED has five PASS, twelve FAIL and zero
ignored. The initial fixture incorrectly required a nonzero token for Root
types and is not credited as functional RED.
The corrected ordinary repair passes all 17 cases plus 47 nominal-type,
21 canonical-consumer and 125 type-inference cases. Independent review then
finds a normalization-budget failure that could bypass duplicate rejection.
Three added exhaustion cases establish a second RED (20 cases / three FAIL).
After the fail-closed repair and six context/snapshot/recovery companions,
all 26 prototype cases and the same three neighboring programs pass with zero
ignored cases. The strengthened recovery test additionally proves successful
normalization after restoring the budget before retrying duplicate detection;
its final native replay also passes 26/26.

This is not complete prototype hygiene. Legacy synthesized prototypes without
a declaration retain their previous lookup behavior. Source union/extern
prototype publication, generic open-definition selection, specialization cache
identity, member/constructor consumers and serialization remain open. Copying
an open generic declaration pointer into a closed prototype alone would not
repair the currently name-based generic cache or definition selection.
The prototype repair does not change `SyntaxContext_Equal` / `StableHash`.
Their separate lower-layer investigation is recorded below.

The local Rust evidence remains namespace-normalized resolution in
`lua/rust/compiler/rustc_resolve/src/ident.rs` and nominal definition identity
in `lua/rust/compiler/rustc_type_ir/src/ty_kind.rs` and
`lua/rust/compiler/rustc_middle/src/ty/adt.rs`. ZR reuses its own existing
semantic declaration identity and does not add a parallel DefId system.

## Source Nominal Publication

Source unions and extern declarations need the same declaration identity as
ordinary nominal types. The separate publication fixture established actual
RED in the shared publisher before producer changes: 19 cases / 15 failures /
zero ignored. The first attempt's empty-variant constructor prerequisite is
recorded separately and is not publisher RED.

The publication contract separates a nominal definition from its projected
type. One reserved TYPE `SymbolId` owns the declaration. `namedTypeBindings`
uses the canonical NOMINAL definition ID; the semantic symbol and type record
use the UNION projection with its variants. Marked definitions use that actual
symbol ID as the nominal token. Root definitions retain token zero so existing
`FromName` projections remain compatible. A generic wrapper is unwrapped to its
nominal definition when preserving the inferred token; this does not redesign
generic definition selection or caches.

The private declaration helper provides raw identifier context and checked ITEM
normalization to both compiler and semantic consumers. Publication retains the
raw context table and stores raw context, while duplicate checks compare valid
normalized identities. Invalid or budget-failed normalization must stop before
records are appended. Registering a declaration after semantic publication
adopts its existing symbol and nominal definition rather than reserving another
identity. The compile-time environment receives the declaration/context binding
without another semantic symbol, following its existing null semantic owner.

Source prototypes retain their original declaration node, so prototype queries
can follow nominal identity back to the proper AST. Repeated compilation of the
same source node is idempotent; a different declaration in the same ITEM context
is rejected. Source extern struct and enum publication use this contract.
Imported metadata prototypes continue to carry a null declaration node because
their temporary parse trees do not share the compiler's source lifetime.

When an annotation creates a provisional non-root nominal binding before the

## Exact Context Queries

The separate context-identity fixture establishes actual RED after a successful
native build: 11 cases / nine failures / zero ignored. The two passing cases
establish equal origins on distinct expansion IDs and existing root/invalid/
cross-owner query rules. The failed cases distinguish three contracts:

- A stable hash is a signature, not exact identity. Origin spans can differ
  while the compatibility-preserving hash bytes remain equal. Nested call-site
  and definition-site equality and import reuse must still distinguish them.
- Queries cannot change identity when an allocator rejects ARRAY scratch.
  Current hashing allocates without a budget transaction; two failed hashes
  can make unequal sites equal, and one can make equivalent sites unequal.
- Import scratch belongs to the destination. Repeated import must not allocate
  in the source owner or publish a duplicate because a source hash failed.

Candidate lower layers were mark-chain validity, expansion registration/site
ownership, stable hashing, exact equality and import reuse. Registration already
maps site contexts into the owner. The observed shared defect is using heap-
dependent hash equality as exact site identity, not prototype construction.
The implementation is isolated in a private identity module. The focused
17-case native replay and six related CTest entries pass. The complete native
replay builds all 126 original outputs and passes all 36 foundation entries.
Its aggregate retains the two diagnostic catalogue failures; the remaining
121 programs retain 108 passes and 13 failures with unchanged result footers.
After that run ends, the defensive fixture guard is added and a fresh build
passes all 17 direct cases and all 36 foundation entries. These results close
this query repair, while the complete M1 acceptance gates remain open.

Each private mark record stores its earliest equivalent local representative
and an unfinalized rolling hash prefix. Publication compares canonical parent
representatives, transparency and exact expansion metadata. Nested call-site
and definition-site contexts use their already-published representatives;
comparison does not recursively revisit expansion trees. Existing raw
`parentExpansionId`, source strings and origin span comparisons are retained.
Public contexts keep the same table/mark shape; no second public identity
system is introduced.

Ordinary append and Normalize's pending marks use one initializer. Normalize
publishes in parent-first order after all fallible reservations, so each parent
and site representative is available. Representatives point only backward or
to the current mark. Growth copies whole private records; abort removes only
the newly appended suffix and restores deferred buffers. Existing mark identities
and hash prefixes need no rollback mutation. `sizeof`-based heap accounting
includes the extra private fields.

`Equal` retains iterative validity checks and root/cross-table rules, then
compares local representatives. `StableHash` finalizes the cached raw-parent
prefix without allocating or changing the previous byte algorithm. Hash
collisions remain valid and must not become equality. Import computes mapped
parent/call-site/definition-site contexts first, then invokes the shared exact
expansion comparator to decide reuse. All import scratch remains destination-
owned and budgeted; public identity queries need no scratch budget reservation.

Local reference evidence is Rust's canonical `(parent, expansion, transparency)`
context map in `lua/rust/compiler/rustc_span/src/hygiene.rs` (allocation at
`alloc_ctxt`), and Mono's separate hash/equality functions in
`lua/mono/mono/metadata/metadata.c` (`mono_metadata_type_hash` and
`do_mono_metadata_type_equal`). ZR retains its existing origin-based expansion
equivalence and stable hash algorithm rather than importing either runtime's
identity representation.

## Exception Flow Binding Context

The source CFG preflight uses the same identifier identities as ordinary
lowering. A direct call in a protected `try/finally` region supplies its target
context to callable lookup. An unresolved same-spelling function in another
context cannot justify an exceptional edge; a matching definition-site
function remains eligible. A runtime companion assigns the marked function's
result and runs a cleanup increment, returning 8 rather than the root
function's 12.

Catch preflight retains the complete `SZrIdentifier`, including context, when
unwrapping a simple primary expression. Parameter reads, direct returns and
rethrows compare normalized local identities. The handler termination check
uses the parameter identifier, so another context's same-name value cannot
stand in for the caught parameter. Prior local reads likewise carry the
unwrapped identifier's context into the initialized-slot query.
All initialized-local queries call the context-aware helper directly.

The restricted two-statement catch alias route has separate source and
destination identities. Its initializer must resolve to the catch parameter;
its final read must resolve to the alias pattern. Collision preflight queries
runtime variables and runtime/comptime functions with these contexts. A root
variable does not occupy a definition-side identity, while an existing matching
identity retains the route's conservative fallback. Type prototype collision
preflight still uses the existing name-based interface and is a separate audit
boundary. The route keeps its existing shape restrictions: mutable private
alias, no type annotation, then a single read.

Negative tests reject mismatched parameter/alias contexts. Positive tests
preserve definition-side reads and independent alias destinations; a runtime
case reads the caught exception payload beside an unrelated root variable and
returns 7. These checks cover the preflight and runtime binding paths without
claiming all typed exception or nominal type queries are context-aware.

## Budget and Transactions

Default macro limits are fuel 1,000,000, call depth 128, heap 64 MiB, aggregate
100,000, generated declarations 10,000, diagnostics 1,024, tokens/nodes 1,000,000,
matching steps 100,000 and expansions 10,000. Zero is a hard resource limit.
Native capacity growth, scratch stacks, decoded strings and AST nodes are all
part of the same expansion's accounting contract.

### Comptime Frame Storage Admission

`compile_time_frame.c` owns private frame storage, binding updates and temporary
value roots. Initialization records parent/state and constructs empty array
metadata; it allocates no backing storage. A literal-only public evaluation can
therefore complete with zero heap allowance without allocating frame vectors.

A new binding or temporary-root record reserves one aggregate entry together
with any required backing allocation. Initial capacity is four. Growth from
four to nine reserves the complete nine-element candidate, not one element or
the five-element difference. Spare capacity requires no new backing charge.
Successful charges are cumulative: freeing replaced storage or the frame does
not refund heap or aggregate usage.

Capacity calculation checks representable element/byte bounds. Admission first
uses a private budget transaction. `TryInit` and copying prepare independent
candidate storage while the old vector remains live. Live-budget commit must
succeed before the nonallocating append/publication replaces that vector.
Failure frees candidate storage and provisional handles without publishing
elements or candidate usage; unrelated live-budget use is not rolled back.
Budget refusal retains its canonical resource, limit and requested usage.

Input name/value objects are checked against the actual state domain and
protected by an AOT stack-root map across candidate allocations and
mutation-boundary polls. Fresh handles are prepared before publication.
Existing-value replacement prepares its new root before releasing the old one.
`isConst` changes only after value replacement succeeds, so a rejected
foreign-domain value cannot freeze a previously mutable binding. The stack map
establishes mark/rewrite protection, not permission to reenter GC from every
shared Core allocator callback. In particular, root-table growth retains its
own coordination-lock restrictions. Forced-GC frame tests prewarm that table
and trigger GC only from the independent frame candidate allocation.

Aggregate header charges remain separate from frame backing. Each public
evaluation admits its initial four-handle root vector when required. Successful
aggregate tests assert both the exact combined charge and, after subtracting
frame backing, the original exact header amount. Private object/array
constructor controls independently verify header-only charges without
bypassing the public evaluator through a null frame.

Builder batches keep old backing vectors alive until commit. New source/tree
records and context imports are prepared on a shadow budget. Context metadata
uses `PrepareBatch` then `PublishBatch`: prepare must not free rollback storage;
the final live-budget delta merge precedes publication. Failure restores arrays,
counts, sources, contexts and roots while preserving unrelated live-budget use.

When the stream and its context table use distinct ledgers, the stream pays for
the combined token/context operation and the table pays for its context-only
delta. Both current live ledgers admit private candidate usage before either
usage is published. A shared ledger is charged once. Rejection preserves the
quota-owning ledger's failure resource, limit and requested usage. `Concat`
snapshots the budget of its freshly owned context table before returning the
sealed stream; sealing a builder does not detach a caller-supplied shared table.

The temporary context table allocation in `Concat` belongs to the same failure
transaction. If the heap budget rejects it before a result stream exists, the
common failure path still copies the resource, limit and requested usage to the
caller. The output stays NULL and committed usage stays unchanged. Both sealed
inputs remain usable for a retry with a restored budget. The eighth limits
regression covers this initial allocation boundary without depending on a
particular native allocation size.

Pending reservations must count before physical allocation, not merely at the
final commit. The peak-heap test specifically reserves context memory and then
requests token storage whose combined cost exceeds the cap. Similarly, the
budgeted parser entry shares the expansion budget while active and detaches its
retained AST owner when the parser state is freed. Failed AST construction must
free collected child trees, not just their pointer container.

The two ownership budget cases first require a healthy token-parser Init: a
live lexer, no parser/fatal/lexical/source-evidence error, the initial LET token
and no exceeded resource. The successful parse must publish an AST, remain
healthy and charge HEAP, NODE_COUNT and FUEL. The rejection case must then fail
specifically at NODE_COUNT limit3, committed usage3/request4, without a
source-evidence failure, and restore the GC-root baseline after cleanup.
Zero FUEL can fail Init before either final behavior contract is established.
The fixture correction supplies default FUEL in both cases; it changes no
production accounting, final oracle or timeout. The root-count assertion bounds
AST-owner/string-root retention in this fixture, not every native memory leak.
Full Windows R16b supplies focused evidence for these assertions only.

Template interpolation uses an embedded text cursor with the outer AST owner,
budget, literal syntax context and origin. Its teardown releases that cursor's
lease without detaching the still-active outer budget. Speculative parser cursor
restore preserves fatal resource errors even while restoring token position.
See `parser-collection-resources.md` for collection ownership and cleanup.

## Validation Boundary

Required independent cases cover deep groups, mismatched delimiters, compound
punctuation, cross-source provenance, empty decoded strings, comments/trivia,
poisoned lexer initialization, checkpoint replay, AST lifetime/GC, atomic failed
imports and exact resource boundaries. Compiler hygiene and controlled evaluator
acceptance are separate gates; native facade tests alone cannot accept M1.

Structured compiler consumers have independent gates in
[prototype lookup](macro-compiler-prototype-lookup.md) and
[receiver member identity](macro-receiver-member-identity.md). Correct publication
or generic cache keys do not alone prove that a later field, call or constructor
consumer retains the selected declaration.
